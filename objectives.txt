# Learning objectives — CUDA-Q QAOA map-coloring tutorial (notebooks 00-04)
# One fixed problem (4-color the Taiwan map: QUBO -> Ising -> QAOA), scaled through
# four simulation strategies. Success is judged by verified samples, not readouts.

00 (baseline, provided):
- Run the full QAOA workflow end to end: QUBO -> spin Hamiltonian -> circuit ->
  optimize -> sample -> verify -> draw on the map.
- Establish the COBYLA baseline: 16 qubits, exact statevector, CPU vs GPU.

01 (better optimizer + GPU tuning):
- At a fixed evaluation budget, the classical optimizer is the cheapest big win:
  Nelder-Mead far below COBYLA's energy, valid-coloring rate up ~5x.
- CUDAQ_* env vars are read at import time: set them BEFORE `import cudaq`;
  changing them needs a kernel restart.
- Time every energy evaluation (milliseconds here) to build a cost baseline.

02 (tensor networks, 36 qubits):
- Statevector hits a hard memory wall: 2^36 x 8 bytes = 550 GB. Tensor networks
  trade that memory for structure-dependent time (tens of seconds per evaluation).
- Encode constraints in the circuit: W-state start + XY mixer keeps evolution in
  the one-color-per-zone subspace — the single biggest lever in the series.

03 (contraction path reuse):
- A tensor-network evaluation = plan + contract. QAOA loops fix the circuit shape,
  so replanning every evaluation is waste: PATH_REUSE caches the plan,
  NUM_HYPER_SAMPLES searches for a better one.
- Prove it end to end: the same-size optimization runs clearly faster than 02's.

04 (approximate MPS, verified answers):
- Approximation quality is task-dependent: chi=16's energy readout is
  untrustworthy, but the sampled colorings — the actual deliverable — match the
  exact backend at equal-or-lower cost, and every answer is verified exactly.
- Memory is the real win: ~0.15 MB vs 550 GB, a calculation, not a measurement.
- Quality has a floor (chi=2 collapses): find it by sweeping, not hoping.

Cross-cutting habits (every notebook):
- Set seeds; hardcode carried values with provenance comments, at full precision.
- Report timing ratios, never raw digits.
- Sample only AFTER optimization; exactly one exact validity assert.
- Budgets: stop and report honestly, never force a result.
- Always draw the final answer back on the map.
